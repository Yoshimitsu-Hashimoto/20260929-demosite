# サイト仕様書

講座用デモサイト「株式会社ひなた」（架空の制作会社）の仕様書です。テスト計画とテストの合否は、この仕様書と [テストデータ](test-data.md) に基づいて判断します。

## 1. 対象と前提

| 項目 | 内容 |
|---|---|
| サイトURL | http://localhost:8090/ |
| 確認用メールボックス | http://localhost:8091/ （Mailpit） |
| 確認する状態 | 管理画面にログインしていない訪問者として確認する |
| テストデータ | [test-data.md](test-data.md) のとおり |
| お問い合わせのテスト前の準備 | 確認用メールボックスを空にしておく |

仕様に書かれていない動作を見つけた場合は、合否を付けず「仕様の確認事項」として記録する。

### 対象外

- 会社案内（`/company/`）、プライバシーポリシー（`/privacy/`）、お知らせ（`/site-open/`）、ヘッダーとフッターの内容
- 管理画面の操作
- デザインの細部（色・余白・フォントなど）の完全な一致
- 表示速度などの性能
- 本番環境へのメール送信

## 2. 制作実績一覧（`/works/`）

公開済みの制作実績を一覧で表示し、業種で絞り込み、制作年で並べ替えられるページ。

| 仕様ID | 受け入れ条件 |
|---|---|
| SPEC-01 | 一覧には公開済みの実績だけを表示する。下書きなど未公開の実績は、一覧・トップページに表示せず、詳細ページのURLを直接開いても表示しない（ページが見つからない表示になる） |
| SPEC-02 | 業種のボタン（例：「飲食」）を選ぶと、その業種に属する実績だけを表示する。他の業種の実績は表示しない |
| SPEC-03 | 「すべて」を選ぶと絞り込みが解除され、公開済みの実績がすべて表示される |
| SPEC-07 | 選んだ業種に該当する実績が0件のときは、「該当する実績はありません。」と表示する |
| SPEC-08 | 一覧の上に、表示している実績の件数を「N件の実績」の形式で表示する。件数は実際に表示している実績の数と一致する。0件のときは「0件の実績」と表示する |
| SPEC-09 | 絞り込みボタン（「すべて」と業種）の並びの中で、選んでいるボタンだけを選択状態で表示する。選択状態のボタンは背景が紺色（`#173b5b`）、文字が白になり、`aria-current="page"` が付く。選んでいないボタンは背景が白 |
| SPEC-14 | 「制作年の新しい順」を選ぶと、制作年の新しい順に並ぶ。「制作年の古い順」を選ぶと、制作年の古い順に並ぶ。制作年が同じ実績は公開日の新しい順に並ぶ |
| SPEC-15 | 制作年が未入力の実績は、どちらの並べ替えでも一覧の最後に表示する（一覧から消えない） |
| SPEC-16 | 並べ替えと業種の絞り込みは組み合わせられる。並べ替えを選んでも業種の絞り込みは解除されず、業種を選んでも並べ替えは解除されない |

### 補足

- 業種のボタンは「すべて」と、登録されている業種（実績が0件の業種を含む）を並べる。実績が0件の業種のボタンも選べる。
- 実績は公開日の新しい順に並べる（並べ替えを選んでいないとき）。1ページにすべて表示し、ページ送りはない。
- 絞り込みはURLで指定する：`/works/?industry=<業種のスラッグ>`。スラッグの大文字と小文字は区別しない。
- `?industry=` のように値が空の場合は「すべて」と同じ扱いにする。
- 存在しない業種を指定した場合は該当0件として扱う（SPEC-07）。このとき、どのボタンも選択状態にしない。ページ自体は通常どおり表示する（HTTPステータスは200）。
- 並べ替えの選択肢は「公開日の新しい順」（初期表示）「制作年の新しい順」「制作年の古い順」の3つ。
- 並べ替えは URL で指定する：`/works/?sort=year_desc`（制作年の新しい順）、`/works/?sort=year_asc`（制作年の古い順）。指定なし・値が空・存在しない値は、公開日の新しい順（今までどおり）として扱う。業種の絞り込みと組み合わせる例：`/works/?industry=food&sort=year_asc`。
- 並べ替えの選択肢の中で、選んでいるものだけを選択状態で表示し、`aria-current="page"` を付ける。
- 並べ替えても、表示する実績と件数（SPEC-08）は変わらない。
- 各実績のカードには、アイキャッチ画像・タイトル・業種名を表示し、カードを選ぶと詳細ページに移動する。

## 3. 制作実績の詳細（`/works/<スラッグ>/`）

| 仕様ID | 受け入れ条件 |
|---|---|
| SPEC-04 | 任意項目「制作年」が未入力の実績では、表に「制作年」の行（見出しと値）を表示しない |
| SPEC-10 | 登録されている項目「顧客名」「制作年」「担当範囲」を表で表示する。制作年は「2026年」のように「年」を付けて表示する |

### 補足

- 詳細ページには、業種名・タイトル・キャッチコピー・アイキャッチ画像・上記の表・本文を表示する。
- 「顧客名」「担当範囲」も、未入力の場合はその行を表示しない（テストデータにはすべての実績に登録されている）。
- 「制作実績一覧に戻る」から一覧（すべて）に戻れる。

## 5. お問い合わせ（`/contact/`）

### 入力項目

| 項目 | 必須 | 入力のルール |
|---|---|---|
| お名前 | 必須 | 空欄不可 |
| メールアドレス | 必須 | 空欄不可。メールアドレスの形式（例：`yamada@example.test`）であること |
| お問い合わせ内容 | 必須 | 空欄不可。複数行を入力できる |
| プライバシーポリシーへの同意 | 必須 | チェックが入っていること |

- 空白（半角スペース・全角スペース・改行）だけの入力は空欄とみなす。前後の空白は取り除いて扱う。
- メールアドレスの形式が正しくない例：`@` がない（`yamada`）、`@` の前または後が空（`@example.test`、`yamada@`）、`@` の後に `.` がない（`yamada@example`）。これより細かい形式の判定は対象外とする。

### 受け入れ条件

| 仕様ID | 受け入れ条件 |
|---|---|
| SPEC-05 | 必須項目のいずれかが未入力、または同意にチェックがない場合、送信できない。送信ボタンを押してもお問い合わせページに留まり、送信完了ページに移動せず、メールも送られない |
| SPEC-06 | すべての項目を正しく入力して送信すると、送信完了ページ（`/thanks/`）に移動して「お問い合わせを受け付けました。」と表示する。確認用メールボックスに、入力した内容のメールが1通届く |
| SPEC-12 | メールアドレスの形式が正しくない場合、送信できない（SPEC-05と同じ扱い） |
| SPEC-13 | 送信できなかった場合、フォームの上に「入力内容に問題があります。」と問題の一覧を表示し、該当する項目の下にもエラーメッセージを表示する。入力済みの内容（同意のチェック状態を含む）は消さずに残す |

### エラーメッセージ

| 条件 | メッセージ |
|---|---|
| お名前が未入力 | お名前を入力してください。 |
| メールアドレスが未入力 | メールアドレスを入力してください。 |
| メールアドレスの形式が正しくない | メールアドレスの形式が正しくありません。 |
| お問い合わせ内容が未入力 | お問い合わせ内容を入力してください。 |
| 同意にチェックがない | プライバシーポリシーへの同意が必要です。 |

複数の条件に当てはまる場合は、当てはまるメッセージをすべて表示する。表示する順番は問わない。
